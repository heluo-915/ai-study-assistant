# AI 学习助手：从入口到全项目的源码逐步阅读路线

适用项目：`D:/Projects/mySecondProject/ai-study-assistant`。依据 2026-11-16 的源码整理；代码改变后，以实际实现为准。建议和 [完整自学手册](../AI学习助手-完整自学手册.md) 配合：本路线重点告诉你**先打开哪里、下一步跳哪里、要看懂什么**。

## 0. 先认识地图：不要从第一个文件一直往下读

你要追的主线，是同一个用户完成一次学习：

```text
注册/登录 → 带 token → 创建笔记 → 生成向量和片段 → 同步 Qdrant
    → 围绕资料提问 → 获取参考片段和回答 → 创建练习题 → 作答/错题/统计
    → 学习任务或学习助手；多轮会话和 SSE 是另一条对话分支
```

对应代码包：`controller` 接收请求；`service` 处理和编排；`mapper` / `repository` 访问数据；`entity` 是实体；`dto` 装请求、响应或中间数据；`security` 和 `config` 管身份、配置；`src/test` 是测试。先理解一条请求怎样穿过它们，再阅读单个类的细节。

**怎么在 IDEA 跳转：**按 `Shift` 两次搜索类名或方法名；按住 `Ctrl` 单击方法名进入定义；按 `Alt+F7` 查找使用位置；`Ctrl+Alt+左方向键` 返回上一次位置。快捷键若被修改，以 IDEA 菜单实际显示为准。用项目搜索查路由时，直接搜 `"/notes/chunks/ask"` 这样的字符串。

每读一个方法，只记六件事：**谁调用它、参数从哪来、做了哪些判断、调用了谁、返回什么、失败怎么办。** 看见不认识的类先写用途，暂时不需要展开它的每个方法；追到目标后再顺调用链回来。

用一份笔记反复填写：

```text
流程/接口：
入口 Controller 和方法：
身份 userId 的来源：
调用顺序：A → B → C
MySQL 表 / Qdrant / 外部模型：
正常返回：
空值、无权限、异常分支：
我还不懂的问题：
```

**学习节奏**：每次只追一个接口，45～90 分钟；先画粗线，再补分支。下面的时间是参考，不是考试期限。运行前先读项目 README；练习时用专用测试库、合成资料与测试账号，避免改动有价值的数据。DeepSeek 调用联网且可能收费。

## 1. 第一遍：弄清一个 HTTP 请求长什么样（约 1 次）

**先看：**[http/学习示例.http](../http/学习示例.http)、[HelloController.java](../src/main/java/com/example/aistudyassistant/controller/HelloController.java)、[application.yml](../src/main/resources/application.yml)。

1. 在 `.http` 文件找一条 `POST`：分出方法、地址、请求头、空行、JSON 请求体。先不用执行所有请求。
2. 在 `HelloController` 找 `@GetMapping` 和 `@PostMapping`，把注解里的路径与 Java 方法对应起来。
3. 在配置里找应用端口、MySQL、Ollama 和 Qdrant。没显式设置的端口不要误认为是业务代码写死。
4. 写下：Controller 方法的输入是什么，返回值如何变成 HTTP 响应？`@RequestBody` 和 `@RequestParam` 有什么不同？

**过关：**能解释“浏览器/HTTP 客户端发请求 → Spring 根据路径找到方法 → 方法返回响应”。这一阶段不需要阅读 Spring 内部实现。

## 2. 第二遍：注册、登录和 userId 从哪里来（约 2 次）

**先画出身份线：**

```text
/register → AuthController.register → AuthService.register → UserRepository
/login → AuthController.login → AuthService.authenticate → JwtService.generateToken
后续请求 → WebConfig → JwtInterceptor.preHandle → JwtService.parseUserId
        → request 属性 userId → @RequestAttribute("userId")
```

**阅读步骤：**

1. 打开 [AuthController.java](../src/main/java/com/example/aistudyassistant/controller/AuthController.java)，看 `register`、`login`。写出它们各自接收的 DTO 和响应。不要把密码、token 抄进笔记。
2. 跳到 [AuthService.java](../src/main/java/com/example/aistudyassistant/service/AuthService.java) 的 `register` 和 `authenticate`；再看 [PasswordConfig.java](../src/main/java/com/example/aistudyassistant/config/PasswordConfig.java) 与 [UserRepository.java](../src/main/java/com/example/aistudyassistant/repository/UserRepository.java)。对照密码是何时编码、何时验证、用户信息由谁读取。
3. 到 [JwtService.java](../src/main/java/com/example/aistudyassistant/service/JwtService.java) 看 `generateToken` 和 `parseUserId`：前者从哪个参数生成令牌？后者验证后返回什么？只看项目调用，不必钻 JWT 库内部。
4. 看 [WebConfig.java](../src/main/java/com/example/aistudyassistant/config/WebConfig.java) 和 [JwtInterceptor.java](../src/main/java/com/example/aistudyassistant/security/JwtInterceptor.java) 的 `preHandle`：哪些路径公开？令牌在哪里读取？成功后把什么放进请求？
5. 回到 [NoteController.java](../src/main/java/com/example/aistudyassistant/controller/NoteController.java)，找任意 `@RequestAttribute("userId")`。它不是客户端 JSON 中随便提交的用户 ID，而是经过前面流程放入请求的属性。

**练习：**用测试账号登录，在专用环境对比有无 Authorization 的受保护请求；若 token 过期重新登录。**过关：**能区分“JWT 验证身份”和“按 userId 判断笔记属于谁”；前者成功并不自动代表用户能访问任意笔记。

## 6. Qdrant：理解异步同步和失败恢复（约 1～2 次）

先打开 [Qdrant接入与验证](Qdrant接入与验证.md)，对照 `application.yml` 中 collection、端口和开关。MySQL 是业务依据；Qdrant 保存片段索引。

2. 读 [NoteVectorSyncScheduler.java](../src/main/java/com/example/aistudyassistant/service/NoteVectorSyncScheduler.java) 的 `processNext`：任务从哪里找？异常怎样记录？开关关闭后会怎样？

4. 回 Mapper 看 `claim`、`finish`：执行期间又有新版本会怎样？普通 FAILED 任务如何重试？注意版本和令牌保护的是任务状态，不是对 Qdrant 的强制写入隔离。
5. 写下中断问题：如果进程在写入中退出，RUNNING 可能卡住；如果仅因为超时就重新派发，但旧进程其实还在运行，会发生什么？目前自动安全恢复未实现，手动操作前必须确认旧执行者停止。

**过关：**能解释 PENDING/RUNNING/SUCCEEDED/FAILED；能说出当前是异步同步和有限重试，不能承诺跨库强一致或自动发现所有损坏。不要拿真实数据直接模拟杀进程，先准备隔离环境。
