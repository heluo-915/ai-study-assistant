# Qdrant 同步任务中断后的手动恢复

当进程在同步期间终止，任务可能停在 RUNNING。`NoteVectorSyncTaskService.recoverAfterWorkerStopped(userId, noteId, expectedToken)` 是内部恢复方法，不提供 HTTP 接口，不自动处理超时。

调用前必须由操作者确认旧进程和所有可能执行同一任务的实例均已停止，才能将任务重新排队。原令牌可在受控的数据库管理环境中从任务记录取得；避免写入公开日志。恢复只影响匹配用户、笔记、RUNNING 状态和原令牌的记录，并保留最新请求版本和动作。重新领取将生成新的令牌，旧令牌无法结束新任务。

这只是数据库状态保护：若旧进程仍在执行，它仍可能继续写入 Qdrant。令牌不会阻止旧进程对 Qdrant 的写入，因此不能据此自动按时间重置任务；多实例、网络中断和租约隔离仍需设计。普通 FAILED 任务已有定时扫描和有限次数的自动重试，并已接入笔记业务；RUNNING 中断任务仍没有自动恢复，也没有完整的运维界面。
