# AI 学习助手：项目架构与关联详解

更新日期：2026-11-16。本页按当前代码和图谱静态整理。静态引用不一定代表实际运行时调用；数字是快照，后续以源码、测试和配置为准。交互查看见 [项目关联图谱](项目关联图谱.html)，按类查询见 [类依赖清单](类依赖清单.csv)，操作说明见 [当前项目说明](当前项目说明.md)。

## 一、项目全貌

这是一个 Spring Boot 单体后端：用户管理自己的学习资料，系统提供检索问答、会话、练习和复习。Java 21、Spring Boot、Spring AI、MyBatis、MySQL、Ollama、DeepSeek 和 Qdrant 在一个项目中协作。

```text
客户端 → JWT 拦截器 → Controller → Service → Mapper / Repository → MySQL
                                      ├→ Ollama：文本向量
                                      ├→ DeepSeek：回答、练习、工具调用
                                      └→ Qdrant：片段向量索引
```

MySQL 保存业务数据和片段，是内容与归属的依据；Qdrant 是额外的检索索引。并非所有接口都经过 Qdrant，也不是每次问答都会触发 Tool Calling。

## 二、代码和数据库怎么分工

本次图谱共统计 **136 个主代码文件、65 个测试 Java 文件**。各文件的静态引用和来源可在 CSV 查看。计数按 Java 文件名进行，不包含非独立文件中的内部类。

| 路径 | 文件数 | 作用 |
| --- | ---: | --- |
| `controller` | 25 | 接收 HTTP 请求、验证参数、转换响应 |
| `service` | 48 | 编排业务、事务、模型调用与检索 |
| `mapper` / `repository` | 10 / 1 | MyBatis SQL、用户数据访问 |
| `entity` / `dto` | 8 / 37 | 实体、请求响应和跨层数据 |
| `config` / `security` / `exception` | 3 / 1 / 2 | 配置、JWT、安全与异常处理 |

主代码另有应用启动文件。图谱按业务域标色、按分层分组；这两种分类角度不同。CSV 中“依赖类数”对同一对类去重，因此与图谱中按不同边类型展示的数量可能不同。反射、框架自动装配和跨进程调用不能由静态引用完整推断。

数据库脚本包括 8 张基础表，以及 `002` 至 `005` 四个迁移：`002`、`003`、`004` 分别新增学习任务、片段构建任务、向量同步任务表；`005` 为同步任务增加重试字段，共 **11 张表**。迁移应根据目标数据库的执行历史确定是否需要运行。

## 三、身份与权限

```text
POST /register → AuthController → AuthService → UserRepository → users
POST /login    → AuthController → AuthService → JwtService → token
受保护请求 → WebConfig → JwtInterceptor → request.userId → Controller / Service
```

`WebConfig` 默认拦截 `/**`，显式放行注册、登录、问候、数据库检查、用户数量和错误路径。令牌证明登录身份；笔记、会话、题目等具体资源仍需通过服务层、SQL 查询或向量过滤验证归属。不能只凭某条 SQL 有无 `user_id` 就判断整条业务链的授权是否正确。

## 四、笔记创建、更新与导入

创建入口包括 `POST /notes`、TXT 上传和 PDF 导入。`NoteCreationService` 编排笔记创建与片段构建，`NoteService`、`NoteMapper`、`NoteEmbeddingService` 参与写入笔记和整篇向量；`NoteChunkBuildService` 调用 `NoteChunkService` 和 `TextChunkService` 准备片段，`NoteChunkPersistenceService` 在事务中复核内容并保存。

创建笔记和片段构建是不同阶段：片段构建失败时，响应可能为 `chunksGenerated=false`，笔记本身可能已经存在。创建阶段失败时应按对应事务和异常判断，不能一概而论。异步上传则通过 `AsyncNoteImportService` 和 `ChunkBuildJobService` 登记并处理 `chunk_build_jobs`；该类任务与下文 Qdrant 同步任务是两套不同任务。

更新路径重点看 `NoteUpdateService` → `NoteUpdatePersistenceService`：先读取本人笔记，在事务外准备整篇向量和片段；再在 MySQL 事务中锁定并核对原始标题和内容，保存新内容及派生数据并登记同步任务。准备失败不改变原笔记，准备期间并发修改会返回冲突。Qdrant 的实际写入发生在另一个异步步骤，不能视为同一数据库事务。

## 五、RAG 检索与回答

```text
问题 → NoteController → NoteChunkAskService → NoteChunkSearchService
     → Qdrant 候选检索 + MySQL 核验，或 MySQL 片段相似度计算
     → 构造参考片段 → ChatService → DeepSeek → answer + sources
```

片段搜索受配置开关影响：启用 Qdrant 时先检查任务状态、模型和数量，并对命中片段回 MySQL 验证；不满足条件或发生异常时回退 MySQL。数量相同、返回内容匹配仍不能发现全部缺失、多余或向量损坏情况；查询开销和召回效果需要实际数据验证。

返回的 `sources` 是给模型的参考片段，不是逐句引用或正确性证明。无相关片段时 `NoteChunkAskService` 直接返回提示。整篇语义搜索、关键词搜索与片段搜索是不同入口，返回粒度也不同，不能混作同一种检索。

## 六、向量同步与故障边界

`NoteVectorSyncTaskService` 和 `NoteVectorSyncTaskMapper` 记录每篇笔记待同步的动作与版本；`NoteVectorSyncScheduler` 定时选择待处理任务，`NoteVectorSyncWorker` 使用令牌领取。UPSERT 先删除该笔记在 Qdrant 的旧向量，再逐片写入；DELETE 清除相关向量。普通失败有有限次数重试，执行过程中出现新版本会重新排队。

**中断恢复尚未自动解决**：执行进程中断可能使任务停留 `RUNNING`；旧令牌只能限制任务状态更新，不能阻止旧执行者继续操作 Qdrant。必须先确认旧执行者已停止，才可按 [手动恢复说明](Qdrant任务手动恢复.md) 处理。MySQL 与 Qdrant 没有共同事务，当前机制不能证明跨库强一致，也不能保证所有异常自动修复。

## 七、会话、题目与工具

- **会话**：`ChatSessionController` 管理会话和消息；`ChatConversationStreamService` 读取历史并流式输出，正常完成且保存成功后发出完成事件。`/chat/stream` 是独立的无会话流式入口，行为不同。
- **练习**：`QuizService` 生成并校验题目，`QuizPersistenceService` 保存；`QuizAnswerService` 处理作答，错题与统计由相应服务查询。错题列表默认包含曾答错的题，也可按最近作答结果筛选。
- **学习助手**：`StudyAssistantService` 通过 Spring AI 注册 `StudyAssistantTools` 的只读工具，查询本人笔记片段、最近仍未答对的题和统计。模型可以选择调用；身份由服务端 `ToolContext` 提供。提示词和归属校验不能证明防御所有提示注入。

## 八、测试与继续阅读

测试分为可控的单元测试、数据库集成测试、模拟 HTTP 与真实依赖测试；部分测试需要显式开启，并非默认全部执行。使用独立测试数据库及测试集合，先检查测试配置和清理范围。历史测试记录只能说明当时的范围，不代表本次重新运行。

建议顺序：`WebConfig` / `JwtInterceptor` → `NoteController` / `NoteService` → 创建与更新服务 → `NoteChunkSearchService` / `NoteChunkAskService` → 会话与练习 → `StudyAssistantTools` → 同步任务。接口与运行入口见 [README](../README.md)，学习练习见 [自学手册](../AI学习助手-完整自学手册.md)。
