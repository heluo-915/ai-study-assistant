# 第二阶段：本机部署与演示

本说明面向 Windows 本机学习演示。Java 21、MySQL 8、Ollama 与 Maven 的准备方法见根目录 README。应用默认只适合本机使用，暂不建议开放公网。

## 数据库升级

现有数据库先备份，再按顺序执行尚未执行的 `database/migrations/002_study_tasks.sql`、`003_chunk_build_jobs.sql`、`004_note_vector_sync_tasks.sql` 和 `005_note_vector_sync_retry.sql`，每个脚本只执行一次。新数据库先执行 `database/schema.sql`，再按编号执行上述迁移。迁移不会删除已有笔记，但请先确认数据库选中正确。无迁移时新功能不可用，后台任务调度会报表不存在。

## 打包和运行

1. 确认本机 MySQL、Ollama 和 Qdrant 运行，模型 `qwen3-embedding:0.6b` 已安装；模型目录按自己的配置设置。
2. 设置 `DB_PASSWORD`、`JWT_SECRET`、`DEEPSEEK_API_KEY`；不要把真实值写进代码或提交。
3. 在项目根目录运行 `mvn test`（使用专用测试库）；通过后运行 `mvn -DskipTests package`。
4. 在已设置环境变量的终端运行 `java -jar target/ai-study-assistant-0.0.1-SNAPSHOT.jar`。端口默认为 8080；首次调用嵌入模型可能较慢。
5. 使用 `http/学习示例.http` 登录；将令牌临时填入 `http/第二阶段演示.http`，依次体验上传任务、状态查询、错题复习计划和助手工具调用。演示后清除令牌。

## 演示讲解顺序

- 从异步上传开始：接口返回笔记和任务编号，轮询任务到成功；失败时可调用重试。任务状态存在数据库中。
- 按第一阶段示例生成题目并故意答错，展示生成当天计划、完成任务、再次生成不重复。
- 向学习助手询问答题统计或错题。模型按需调用工具；工具只能访问服务器传入的当前用户身份。模型可能选择不调用工具，回答需要核对。
- 展示资料问答返回的来源；说明相似资料仍可能互相干扰以及模型回答不保证正确。

## 已知边界

- 当前后台调度适合单机学习演示；运行超过 30 分钟的任务会被视为失联并重新排队。长任务、进程暂停和多实例并发会带来重复计算，暂未做心跳和分布式任务队列。
- 任务失败返回通用错误提示，详细原因需结合服务日志排查；SQL、调用延迟、模型错误和用户输入不应记录密钥或完整私有文本。
- 工具只读，用户身份通过服务端上下文提供；尚需测试更多提示注入、调用循环以及生产环境资源限制。
- `GET /database-check` 等学习演示接口、身份校验和资源限制仍需生产安全加固。
